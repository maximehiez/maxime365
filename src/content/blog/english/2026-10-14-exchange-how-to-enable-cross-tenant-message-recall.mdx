##### Introduction
Cloud message recall has so far only worked within a single tenant. *Cross-Tenant Message Recall* extends this capability to trusted organizations : a sender from an authorized tenant can now recall a message sent to a recipient in another Microsoft 365 tenant, exactly as they would internally.

Control remains entirely on the side of the tenant receiving the message. A cross-tenant recall is only honored if the recipient tenant's administrator has explicitly added the sender tenant to an allow list.

---

##### Prerequisites
**<u>Administrator role</u>**
- An account with the *Global Administrator* or *Exchange Administrator* role to access Microsoft Exchange Online.

---

##### Step 1 : Connect to Microsoft Exchange Online in PowerShell
Connect to Microsoft Exchange Online using the following PowerShell command :
```powershell
Connect-ExchangeOnline
```

---

##### Step 2 : Check the current configuration
Check whether cross-tenant recall is enabled and which external tenants are already allowed using the following PowerShell command :
```powershell
Get-CrossTenantRecallConfiguration
```

The result looks like this :
```powershell
CrossTenantRecallEnabled AllowedSenderTenantIds
------------------------ -----------------------
False                    {}
```

<Notice type="note">Cross-tenant recall is disabled by default.</Notice>

---

##### Step 3 : Enable recall on the 1st tenant
Enable the feature for your tenant using the following PowerShell command :
```powershell
Set-CrossTenantRecallConfiguration -CrossTenantRecallEnabled $true
```

---

##### Step 4 : Allow a sender tenant
Add the tenant ID to allow to the *-AllowedSenderTenantIds* parameter using the following PowerShell command :
```powershell
Set-CrossTenantRecallConfiguration -AllowedSenderTenantIds @{Add="11111111-2222-3333-4444-555555555555"}
```

To allow several tenants in a single command :
```powershell
Set-CrossTenantRecallConfiguration -AllowedSenderTenantIds @{Add="11111111-2222-3333-4444-555555555555","66666666-7777-8888-9999-000000000000"}
```

<Notice type="tip">The sender tenant's administrator retrieves their own tenant ID using the command *Get-ConnectionInformation | fl TenantID*, from an Exchange Online PowerShell session connected to their tenant.</Notice>

---

##### Step 5 : Enable recall on the 2nd tenant
Apply the same configuration on the 2nd tenant.

##### Removing an allowed tenant
If you want to adjust the configuration and remove one or more tenants from the allow list, you can do so using the following PowerShell command :
```powershell
Set-CrossTenantRecallConfiguration -AllowedSenderTenantIds @{Remove="11111111-2222-3333-4444-555555555555"}
```

---

##### Limitations to know
Cross-tenant recall remains confined to the boundaries of Exchange Online. It doesn't work for a recall sent to the internet or to an organization outside Exchange Online, and hybrid customers can't recall a message sent from a cloud mailbox to an on-premises Exchange environment.

<Notice type="warning">Allowing an external tenant to recall messages is equivalent to giving it deletion power over content already delivered to your mailboxes. Some organizations prefer not to enable this feature for compliance reasons, particularly when the messages involved are subject to a retention obligation.</Notice>
