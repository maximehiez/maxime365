##### Introduction
*Microsoft Entra* passkey on *Windows* lets you register a device-bound passkey directly in the local *Windows Hello* container, to sign in to *Microsoft Entra ID* with Windows Hello biometrics or PIN, without the device being joined or registered to Entra ID. Worldwide and GCC rollout finished mid-June 2026, and GCC High and DoD rollout has been underway since early October 2026, with completion expected by the end of October 2026.

Check the article on activating Microsoft 365 Passkey [HERE](https://maxime.hiez.ca/en/blog/2024-12-16-entra-how-to-activate-passkey), which covered the general activation of the *Passkey (FIDO2)* method. This new capability builds on that same method, adding *Windows Hello* as a supported passkey provider.

---

##### Prerequisites
**<u>Required licenses</u>**
- *Microsoft 365* (any edition supporting modern authentication).

**<u>Administrator role</u>**
- An account with the *Global Administrator* or *Authentication Policy Administrator* role to configure the passkey profile.

**<u>Other</u>**
- a *Windows 10* or *Windows 11* PC, on a device supporting *Windows Hello*.
- The *Passkey (FIDO2)* authentication method enabled.

---

##### Step 1 : Sign in to the Microsoft Entra Admin Center
Sign in to the Microsoft Entra Admin Center by opening your web browser to https://entra.microsoft.com.

---

##### Step 2 : Configure the passkey profile for Windows Hello
In the left-hand menu, click *<u>Authentication methods</u>*, then *<u>Passkey (FIDO2)</u>*, and *<u>Configure</u>*.

Click *<u>Add profile</u>*, select *<u>Device-bound</u>* as the passkey type, and add the *<u>Windows Hello</u>* AAGUID via *<u>Add AAGUID</u>*.

![image](/images/blog/entra/tuto/entra_how_to_enable_passkey_on_windows_001.png)

<Notice type="note">The profile must not enforce attestation (*Enforce attestation* disabled), otherwise Windows passkey registration fails.</Notice>

---

##### Validate the result
Once the profile is saved, each user can register a Windows passkey from *My Sign-Ins*, by signing in at https://mysignins.microsoft.com/security-info, and choosing *<u>Add sign-in method</u>*, then *<u>Passkey</u>*. The passkey is then created and stored in the device's local Windows Hello container.

![image](/images/blog/entra/tuto/entra_how_to_enable_passkey_on_windows_002.png)

To sign in afterward, the user opens a Microsoft Entra ID resource, selects *<u>Face, fingerprint, PIN, or security key</u>* as the sign-in method, then validates with Windows Hello.

<Notice type="warning">If a *Windows Hello for Business* credential already exists for the same account on the device, Windows passkey registration fails. These two methods can't coexist for the same account in the same Windows Hello container.</Notice>

---

##### What sets this method apart from Windows Hello for Business
- <u>Registration</u> : Initiated by the user, with no device join or registration required, unlike *Windows Hello for Business*, which provisions automatically during device enrollment.
- <u>Device sign-in</u> : Not supported. Windows passkey only enables sign-in to Microsoft Entra ID, not Windows session sign-in or the associated SSO.
- <u>Management</u> : Driven by Entra ID's *Authentication methods* policy, not by *Microsoft Intune* or a *Group Policy*.
- <u>Multiple accounts</u> : A single Windows device can store a separate passkey for several Microsoft Entra accounts.

---

##### Conclusion
You now know how to enable Microsoft Entra passkey on Windows, to allow a phishing-resistant sign-in on personal, shared, or non-Entra-joined devices.
