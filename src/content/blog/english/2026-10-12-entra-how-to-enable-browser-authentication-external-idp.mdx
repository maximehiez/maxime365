##### Introduction
*Microsoft* announced the general availability of browser authentication for external identity providers in *Entra ID*. For domains federated through *WS-Fed* or *SAML 2.0*, the external identity provider authentication step now runs in the system browser instead of an embedded *WebView*, which makes it possible to use Passkeys and *FIDO2* security keys issued by that provider to sign in to *Outlook*, *Teams*, *OneDrive*, *Word*, *Excel*, *PowerPoint*, and *Microsoft To Do* on Android, iOS, and managed macOS.

Check the article on migrating from SMS and voice to Passkey [HERE](https://maxime.hiez.ca/en/blog/2026-07-30-entra-how-to-migrate-sms-voice-to-passkey), which noted that Passkey support for *B2B* accounts was still to come. A separate effort also closes that gap on the guest side : since early October 2026, B2B users can register a Passkey from the resource tenant to satisfy that tenant's MFA requirements.

---

##### Prerequisites
**<u>Required licenses</u>**
- *Microsoft Entra ID*, on a domain federated through WS-Fed or SAML 2.0.

**<u>Administrator role</u>**
- An account with the *Global Administrator* role or the *Domain-InternalFederation.ReadWrite.All* and *Domain.ReadWrite.All* permissions, to modify the federation configuration.

**<u>Other</u>**
- The *Microsoft Graph PowerShell* module installed.
- An up-to-date system browser and broker app for the targeted platform : *Chrome* on Android, *Safari* on iOS and managed macOS, with *Microsoft Authenticator* or *Intune Company Portal* as the broker.

---

##### Step 1 : Sign in with Microsoft Graph PowerShell
Sign in with the Microsoft Graph module using the following PowerShell command :
```powershell
Connect-MgGraph -Scopes "Domain-InternalFederation.ReadWrite.All"
```

---

##### Step 2 : Identify the domain's federation configuration
Retrieve the configuration identifier for the federated domain in question. This identifier is needed for the next, activation step.
```powershell
Update-MgDomainFederationConfiguration -DomainId 'domain.com'
```

---

##### Step 3 : Enable browser authentication for the desired platforms
Enable the feature on the federation configuration identified in step 2, specifying the platforms involved among *Android*, *iOS*, and *macOS*.
```powershell
Update-MgDomainFederationConfiguration -DomainId 'domain.com' -InternalDomainFederationId '<guid>' -SystemBrowserEnabledOn "Android iOS"
```

Setting *SystemBrowserEnabledOn* to *none* disables the feature.

---

##### Step 4 : Verify the applied configuration
Query the configuration again to confirm that the desired platforms are indeed enabled.
```powershell
Update-MgDomainFederationConfiguration -DomainId 'domain.com' -InternalDomainFederationId '<guid>'
```

---

##### Validate the result
To confirm that the configuration works, start a sign-in from a supported Microsoft app on an eligible device. The system browser should open for the external identity provider authentication step. Once that authentication is complete, a redirect link returns the user to the originating app through the broker.

<Notice type="info">If sign-in stays in an embedded WebView, check that the domain is indeed federated through *WS-Fed* or *SAML 2.0*, that the platform is enabled in the federation configuration, and that the browser and broker versions meet the minimum requirements.</Notice>

---

##### Supported platforms and apps
| Platform       | Required browser | Minimum broker                                                                                |
| :------------: | :--------------: | :-------------------------------------------------------------------------------------------: |
| Android        | Chrome (default) | Microsoft Authenticator 6.2510.6857, Link to Windows 1.25102.138.0, Company Portal 5.0.6768.0 |
| Shared Android | Chrome           | Android broker compatible with the applicable minimum                                         |
| iOS            | Safari           | Microsoft Authenticator 6.8.29 (6.8.37 recommended)                                           |
| Managed macOS  | Safari           | Intune Company Portal 5.2511                                                                  |

The Microsoft apps tested and supported for this experience are *Outlook*, *Teams*, *OneDrive*, *Word*, *Excel*, *PowerPoint*, and *Microsoft To Do*.

<Notice type="note">Linux, unmanaged macOS, and social *OAuth2*/*OIDC* identity providers aren't supported. On Windows, third-party FIDO authentication is already native and doesn't use this mechanism. Direct sign-in to Company Portal on Android also remains in an embedded WebView.</Notice>
